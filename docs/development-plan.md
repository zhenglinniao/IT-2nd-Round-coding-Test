# 开发与验收记录

## 需求来源

原始 Coding Test 为基础；HTML 是 AI 辅助整合与 FAQ 补充，不自动覆盖原题。SQL.url 是原查询链接的替换入口。原始文件含凭据和个人信息，整个目录排除 Git 提交。

## 实施口径

- 原 PDF 第二张订单表头为 PO-20251202-00046，商品明细为 PO-20251203-00046；采用后者，保留来源差异记录。
- RRP 已含 GST。采用补充说明的未税计算方式，避免重复加税；这是本项目采用的明确口径，不能表述为出题人已正式确认。
- Decimal：单价及行金额保留完整精度参与计算，订单未税小计 = round(各行未舍入金额之和, 2)，GST = round(未舍入订单小计 × 10%, 2)，总额 = 已舍入小计 + 已舍入 GST + 运费。ROUND_HALF_UP；显示单价和小计不参与后续税额计算。实际样例中订单一各行显示值之和比订单未税小计高 A$0.01，因此另列 rounding_adjustment 对齐展示行金额与订单汇总，避免逐行舍入或使用已舍入小计计税导致订单总额增加。这是对初版计划舍入方案的实测修正。
- Python + React，符合两份题目的技术栈交集。提供完整前后端。
- 每张订单独立；一个订单可以有多个包裹，一个包裹可以关联多条商品明细。
- 缺商品或非法数量时不生成误导性的完整订单总额。产品尺寸缺失不影响商品金额，但阻止相应运费估算。
- Australia Post / StarTrack 实现只读查询。TNT 研究与接口核验纳入实施，若缺乏匹配所给账号的有效协议，明确返回未配置/未实现，相关费用为零；不将 HTML 的“可选”直接当成原题要求失效。
- 无新增订单、支付、登录、数据库、上传或公网部署。更换符合结构的 JSON 后重启即可处理新订单。

## 开发顺序

1. 核实 SKU 入口、字段、单位与快递协议，记录实际结果。
2. 数据校验、商品匹配、Decimal 计算、按订单隔离。
3. 前端列表/详情、商品和地址、金额与错误状态。
4. 快递适配、超时/权限/空数据/错误格式，独立刷新和请求合并。
5. 可选运费公式，按包裹计费后汇总订单；明确估算。
6. 中文文档、自动测试、真实接口烟雾验证、构建及浏览器检查。

## 必要测试

- 金额的固定人工期望值：单行、多行、循环小数、舍入、零价。
- 数据：缺 SKU、非法数量、重复主键、无效引用、损坏文件、空订单集，单订单错误隔离。
- 物流：成功、多种结构、运单不匹配、缺字段、空结果、401/403、429、5xx、超时、非 JSON。自动测试不依赖实时网络。
- 运费：单位、数量、体积重量、重复包裹、缺尺寸、TNT 为零。
- API：列表/详情/404/物流局部失败/无凭据不请求外部接口。
- 前端：切换订单、加载/错误/空状态、金额不完整、物流失败后恢复。
- 端到端：两订单与多包裹展示、未知订单和失败状态；构建通过、README 可启动、凭据无泄漏。
